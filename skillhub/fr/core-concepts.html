Concepts Fondamentaux d'OpenStack

Difficulté : Débutant · Durée estimée : 15 min

OpenStack est un système d'exploitation cloud qui contrôle de grandes piscines de ressources de calcul, de stockage et de réseau dans un centre de données, toutes gérées par un tableau de bord ou via l'interface en ligne de commande. Il est composé de services indépendants qui travaillent ensemble pour fournir une plateforme de calcul cloud complète.

Comprendre les Services OpenStack

Nova - Service de Calcul

Nova est le service principal responsable de la gestion et de l'approvisionnement des machines virtuelles (instances) dans OpenStack. Il gère le cycle de vie des instances, y compris leur création, leur planification, leur exécution et leur terminaison. Nova fonctionne avec divers hyperviseurs tels que KVM, Xen, VMware et Hyper-V.

Neutron - Service de Réseau

Neutron fournit le réseau comme service pour OpenStack. Il permet aux utilisateurs de définir et de gérer les réseaux virtuels, les sous-réseaux, les routeurs et les pare-feux. Neutron supporte diverses topologies réseau et peut s'intégrer à l'infrastructure réseau physique.

Cinder - Service de Stockage Bloc

Cinder fournit un stockage persistant pour les instances gérées par Nova. Il permet aux utilisateurs de créer, attacher et détacher des volumes de stockage qui peuvent être utilisés par les machines virtuelles. Cinder supporte divers backends de stockage y compris le stockage local, le SAN et le NAS.

Keystone - Service d'Identité

Keystone est le service d'identité d'OpenStack qui fournit l'authentification et l'autorisation pour tous les autres services OpenStack. Il gère les utilisateurs, les tenants (projets), les rôles et les services. Keystone supporte diverses méthodes d'authentification y compris le nom d'utilisateur/mot de passe, les jetons et les identifiants d'application.

Dans OPCP Core, Keystone est fédéré par Keycloak, qui est le Identity Provider pour l'ensemble du niveau 1. Keystone et Keycloak fonctionnent tous deux dans le contrôleur OPCP.

Glance - Service d'Images

Glance sert de service d'images dans OpenStack, stockant et récupérant les images de machines virtuelles. Il supporte divers formats d'images et fournit une gestion des métadonnées pour les images. Les utilisateurs peuvent télécharger, télécharger et gérer les images utilisées pour créer des instances.

Concepts Clés

Projets (Tenants)

Les projets sont des unités organisationnelles dans OpenStack où les ressources telles que les instances, les réseaux et les volumes sont regroupées. Chaque projet dispose de son propre ensemble d'utilisateurs et d'autorisations, permettant l'isolement et la gestion des ressources.

Endpoints

Les endpoints sont des URL qui exposent les services OpenStack. Chaque service expose des endpoints HTTP que les clients peuvent interroger pour interagir avec le service. Ces endpoints sont listés dans le catalogue de services Keystone après authentification.

Authentification

L'authentification dans OpenStack est gérée par Keystone. Les utilisateurs peuvent s'authentifier en utilisant diverses méthodes y compris le nom d'utilisateur/mot de passe, les jetons ou les identifiants d'application. Une fois authentifié, les utilisateurs reçoivent un jeton qui leur donne accès aux services OpenStack.

Comment Ils Fonctionnent Ensemble

Ces services fonctionnent ensemble pour fournir une plateforme de calcul cloud complète. Par exemple, lors de la création d'une nouvelle instance :

  1. Keystone authentifie l'utilisateur et lui fournit un jeton
  2. Neutron crée la connectivité réseau nécessaire
  3. Cinder provisionne les volumes de stockage
  4. Nova lance la machine virtuelle avec les ressources spécifiées
  5. Glance fournit l'image de base pour l'instance

Résumé

  • OpenStack se compose de services indépendants qui travaillent ensemble pour fournir des capacités de calcul cloud
  • Nova gère les machines virtuelles, Neutron gère le réseau, Cinder fournit le stockage, Keystone gère l'identité, et Glance gère les images
  • Les ressources sont organisées en projets pour l'isolement et la gestion
  • Tous les services communiquent via des API standard accessibles via des endpoints
