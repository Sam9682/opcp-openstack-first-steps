Compute

Difficulté : Intermédiaire · Durée estimée : 25 min

  • Dans la leçon précédente, nous avons créé le réseau nécessaire à un serveur pour communiquer.
  • Nous allons maintenant déployer un serveur grace au service compute Nova.

1. Assigner un nœud à votre projet

Avant de pouvoir déployer une instance, un admin doit assigner un nœud baremetal au projet que vous avez créé dans la leçon Gestion des utilisateurs. Nova ne peut planifier des instances que sur des nœuds appartenant à votre projet.

Vous devez être administrateur pour effectuer ce qui suit.

Listez les nœuds disponibles et notez le <node-id> que vous souhaitez utiliser : 

openstack baremetal node list

Transférez ensuite la propriété de ce nœud à votre projet (${OS_PROJECT_ID} a été défini dans la leçon précédente) : 

openstack baremetal node set <node-id> --owner ${OS_PROJECT_ID}

Vérifiez que le nœud appartient maintenant à votre projet : 

openstack baremetal node show <node-id> -f value -c owner

2. Paire de clés SSH — Générer et enregistrer

Pour vous connecter à votre instance via SSH, vous avez besoin d'une paire de clés. La clé publique est injectée dans l'instance au démarrage, et vous utilisez la clé privée correspondante pour vous authentifier.

Générer une paire de clés localement

# Générer une paire de clés SSH Ed25519 (recommandé)
ssh-keygen -t ed25519 -C "${STUDENT_ID}@lab" -f ~/.ssh/${STUDENT_ID}-key -N ""

# Cela crée deux fichiers :
#   ~/.ssh/${STUDENT_ID}-key       (clé privée — à garder secrète)
#   ~/.ssh/${STUDENT_ID}-key.pub   (clé publique — envoyée à OpenStack)

Vous pouvez aussi utiliser RSA si Ed25519 n'est pas supporté : 

ssh-keygen -t rsa -b 4096 -C "${STUDENT_ID}@lab" -f ~/.ssh/${STUDENT_ID}-key -N ""

Enregistrer la clé publique dans OpenStack

# Importer votre clé publique dans OpenStack
openstack keypair create \
  --public-key ~/.ssh/${STUDENT_ID}-key.pub \
  ${STUDENT_ID}-keypair

# Vérifier que la keypair est enregistrée
openstack keypair show ${STUDENT_ID}-keypair

3. Lancer une instance

Utilisez le CLI openstack pour lancer une instance avec un flavor, une image et votre paire de clés SSH. Nommez-la ${STUDENT_ID}-compute-instance.

Utilisez l'utilisateur créé dans le lab "User Management" lab, qui à le rôle "member".

Par défaut, OpenStack sélectionne un hôte en fonction du flavor choisi et des règles du scheduler, ce qui ne garantit pas que le nœud que vous venez de configurer sera utilisé.

Pour vous assurer que votre instance sera déployée sur ce nœud précis, vous pouvez cibler ce dernier utilisant sa zone de disponibilité : 

openstack server create --availability-zone "nova::`<node-id>`"

Les images par défaut sur OPCP Core n'ont pas de mot de passe défini. Si vous voulez fournir un mot de passe pour pouvoir vous connecter via la console de l'instance, utilisez des fichiers Cloud-init. Voici un exemple de configuration basique utilisateur/mot de passe pour Debian 12 dans un fichier cloud-init.yaml (DOIT commencer par la ligne #cloud-config) : 

#cloud-config
users:
  - name: debian
    lock_passwd: false
    plain_text_passwd: 'debian'
    sudo: ['ALL=(ALL) NOPASSWD:ALL']
ssh_pwauth: true 
# Lancer une instance de Compute
openstack server create \
  --flavor scale-1 \ # modèle d'instance à utiliser
  --image "Debian 12 LVM OPCP" \ # image système à déployer
  --network ${STUDENT_ID}-net \ # (SI PAS DE TRUNK) réseau auquel attacher l'instance (un port standard sera créé et attaché)
  --port ${STUDENT_ID}-trunk-port \ # (SI TRUNK) attacher le port trunk créé auparavant
  --availability-zone "nova::`<node-id>`" \ # sélectionner un nœud spécifique, nécessaire quand vous avez pré-configuré un nœud spécifique
  --key-name ${STUDENT_ID}-keypair \ # clé SSH publique à utiliser
  --user-data ./cloud-init.yaml \ # fichier cloud-init
  ${STUDENT_ID}-compute-instance # Nom de l'instance

# Vérifier que l'instance est active
openstack server show ${STUDENT_ID}-compute-instance -f value -c status

Se connecter à l'instance via SSH

# Récupérer l'adresse IP de l'instance
IP=$(openstack server show ${STUDENT_ID}-compute-instance -f value -c addresses | grep -oP '[\d.]+')

# Se connecter avec votre clé privée
ssh -i ~/.ssh/${STUDENT_ID}-key ubuntu@$IP

Si vous avez configuré un nœud multi-NIC avant le déploiement, vous pouvez maintenant agréger ses interfaces au niveau OS pour plus de bande passante et de redondance — voir l'annexe optionnelle Configuration LACP.

Si vous avez configuré le RAID logiciel sur ce nœud avant le déploiement, consultez l'annexe optionnelle RAID Logiciel pour vérifier la configuration RAID depuis l'instance.

Résumé

  • Transférez la propriété d'un nœud baremetal à votre projet avec openstack baremetal node set --owner avant de déployer.
  • Générez une paire de clés SSH avec ssh-keygen et enregistrez-la avec openstack keypair create.
  • Utilisez --key-name lors de la création d'une instance pour injecter la clé publique.
  • Utilisez les commandes openstack server pour lancer des instances.
  • Les flavors définissent le CPU, la RAM et le disque alloués à une instance.
  • Les erreurs de flavor ou d'image manquants sont signalées avec des messages clairs par le CLI.
  • Voir l'annexe Configuration LACP pour agréger des interfaces réseau et gagner en bande passante et en redondance.
  • Voir l'annexe RAID Logiciel pour configurer et vérifier l'état du RAID logiciel.
