User Management

Difficulty: Beginner · Estimated time: 20 min

Before authenticating against OpenStack, you need a user account. OPCP Core relies on Keycloak as its identity provider, which federates with Keystone to issue project-scoped OpenStack tokens. This lesson walks you through the full setup: reviewing the built-in roles, configuring the OIDC client that links Keycloak to Keystone, creating an OpenStack project, creating a user and assigning it the right role and project attributes, and verifying that the user can authenticate. By the end of this lesson, you will be able to:

  • Identify the four built-in roles — Master Admin, IT Admin, DC Operator, and Reader — and what each one grants.
  • Configure the Keycloak client (scopes, group attribute mapper, and audience mapper) that Keystone uses for federation.
  • Create a new OpenStack project (tenant) to scope a user's resources.
  • Create a user in Keycloak and set their initial credentials.
  • Configure the user's role and project attributes so they map correctly to OpenStack.
  • Create environment variables and authenticate with the Openstack CLI.

1. Log into Keycloak

For this lab, you should have been provided an admin account on Demo OPCP platform. Go to https://admin.keycloak.<FQDN> to authenticate. You can find your FQDN in your welcome.md file

2. Built-in Roles

After the very first installation of OPCP, a super-admin account (login / password) is communicated to you. This account is used to connect to the Keycloak UI (or API) and manage users.

Keycloak realms, roles, and groups are pre-configured out of the box. The OPCP solution is delivered with the following built-in roles:

  • Master Admin role — the pre-configured super-admin delivered with OPCP.
  • IT Admin — administers OpenStack projects and manages resources for end-users.
  • DC Operator — operates the data-center infrastructure layer.
  • Reader — read-only visibility, with only partial read access on OpenStack resources.

Each of these OPCP roles (defined in Keycloak) maps to a set of OpenStack roles once the token reaches Keystone:

OPCP role (Keycloak) OpenStack roles
Master Admin role reader, member, admin
IT Admin reader, member, admin
DC Operator None
Reader reader (partial)
Other platform resources: the table above only covers OpenStack roles. OPCP also manages access rights for other resources such as Grafana, Netbox, and Prometheus — these are detailed in the official IAM Rights Management documentation.

3. Client Setup

3.1. Create a new client

Clients are used by applications or services (as opposed to users) to interact with Keycloack for authentication or authorisation. In this lab, we will create a client for the openstack CLI client.

Log in to your Keycloak instance (https://admin.keycloak.FQDN) and select the realm in which the OpenStack users are defined (choose master by default). Create a new client. Go to the Clients section and click on Create a client. Enter a Client ID in the format ${STUDENT-ID}-cli, for example: jdoe-cli. Client type must be OpenID Connect. Click on Next.

3.2. Enable client authentication

Enable Client Authentication (set to ON).
Authentication Flow must have both Standard Flow and Direct Access grants
Click on Next, then on Save.

3.3. Configure scopes (Client Scopes)

Scopes contain pieces of information (named claims) that are included in tokens, such as roles, user attributes or custom data (e-mail, organisation, etc.). When the server receives the token, it uses these claims to identify the client.

In the client you just created, open the Client Scopes tab (as opposed to the generic "Client scopes" page in the left panel). Select the scope named: [your-client-id]-dedicated. Click on Configure a new mapper.

3.4. Add a user group attribute mapper

Choose the "By Configuration" mapper type Aggregate User/Group Attribute (as JSON String). Configure the following fields :

Field Value
Name projects
Attribute Name project
Token Claim Name projects
Warning: the Attribute Name value is project, without a trailing "s". All the other field values use projects, with a trailing "s".

Click on Save.

3.5. Add an audience mapper

Warning: as of OPCP version 3.0.5, you must add an audience mapper to the client so that the issued tokens include the keystone audience.

From the Client Scopes tab, select the [your-client-id]-dedicated scope again, then click Configure a new mapper and choose the Audience mapper type. Configure the following fields:

Field Value
Name keystone-audience
Included Client Audience keystone
Included Custom Audience (leave empty)

Click on Save.

3.6. Retrieve the client credentials

Go to the Credentials tab of the client you just created. Copy and securely store the Client Secret — it will be needed when configuring the OpenStack CLI.

3.7. Retrieve the admin project ID from OpenStack Horizon

In a new browser tab, go to https://admin.dashboard.<your-FQDN> then Horizon - Project > API access > View Credentials and copy/paste the project ID. Store it for next steps.

3.8. Setup your environment variables

Manually adapt the following information and copy it into an openrc.sh file. Change information between <>. 

export OS_INTERFACE=public
export OS_IDENTITY_API_VERSION=3
export OS_AUTH_URL=https://keystone.<your-FQDN>
export OS_AUTH_TYPE=v3oidcpassword
export OS_PROTOCOL=openid
export OS_IDENTITY_PROVIDER=keycloak-admin
export OS_CLIENT_ID=<your-client-id>
export OS_CLIENT_SECRET=<your-client-secret>
export OS_DISCOVERY_ENDPOINT=https://admin.keycloak.<your-FQDN>/realms/master/.well-known/openid-configuration
export OS_USERNAME=<your-username>
export OS_PASSWORD=<your-user-password>
export OS_PROJECT_ID=<your-project-id>
export OS_CACERT=<path-to-cert-if-needed>
export http_proxy=<proxy-url-if-needed>
export https_proxy=<proxy-url-if-needed>

Source openrc.sh to load environment variables (the current directory in the terminal should be where the file is located)

source openrc.sh
Warning: on Windows, it is recommended to create and edit the openrc.sh file with a Linux editor (e.g. vim or nano) rather than a Windows editor, as Windows editors can introduce encoding issues. It is also possible to copy/paste the content manually.

4. Create a new project

Before creating users, you may need to create OpenStack projects (also known as tenants). Projects are organizational units in OpenStack where resources such as instances, networks, and volumes are grouped.

In OPCP, projects are typically created through via the command line interface. Here's how to create a new project:

Using the OpenStack CLI

To create a new project using the OpenStack CLI, you need to have administrative privileges. Run the following command: 

# Create a new project
openstack project create ${STUDENT_ID}-project --domain keycloak-admin

You can also specify additional options when creating a project: 

# Create a project with description and enabled status
openstack project create --description "My new project for testing" --enable ${STUDENT_ID}-project --domain keycloak-admin
You must not use Horizon interface to create projects in OPCP because it does not provide a way to chose a specific domain.

5. Creating a User in Keycloak

Log in to the Keycloak administration console with the super-admin credentials, then navigate to Users → Add user. Fill in the required fields (username, email, first / last name) and save.

Setting a Password

After creating the user, open the Credentials tab and click Set Password. Enter the initial password. Enable the Temporary toggle if you want the user to be prompted to reset their password at first login.

Configuring the role

For this workshop we will use an IT Admin role: open the Role Mapping tab and click Assign Role -> Client Role. Choose it_admin.

6. Configuring User attributes

When you need to create an IT Admin — someone who administers OpenStack projects and manages resources for end-users — you must add a project attribute to the user.

What this attribute is for: this is the data source for the project attribute mapper you configured earlier (step 3.4). When the user authenticates, that mapper reads this key-value pair from the user and embeds it in the token as a claim; Keystone then reads the claim and grants the user the specified role(s) on the specified project. In other words, this is where you tell Keycloak which OpenStack project and role a given user should resolve to — it's the "3. User authenticated" → "4. Map attributes to OpenStack resources" hand-off shown in the authentication flow diagram at the top of this page.

Open the Attributes tab of the user and add a key-value pair:

  • Key: project
  • Value: a single-line JSON object (see below)
{"domain": {"name": "keycloak-admin"}, "name": "jdoe-project", "roles": [{"name": "member"}]}

Adapt the values to match your setup:

  • domain → name — the OpenStack domain (keep keycloak-admin unless you are using another domain on your controller).
  • name — the OpenStack project name (e.g. jdoe-project. In your case, use ${STUDENT_ID}-project).
  • roles — the OpenStack roles to grant (keep member).

7. Test user authentication using openrc file

Copy your previous openrc file and modify your environment variables to authenticate as your new user. Modify following values :

  • OS_USERNAME
  • OS_PASSWORD
  • OS_PROJECT_ID

openstack token issue should work and openstack baremetal node list should return empty response.

Source back your admin openrc file, we will need it for next steps.

Summary

  • OPCP ships with pre-configured Keycloak realms, roles, and groups.
  • Four built-in roles: Master Admin role, IT Admin, DC Operator, and Reader.
  • User passwords are set in the Credentials tab; enable Temporary to force a reset on first login.
  • IT Admins receive a project attribute on the keycloak-admin domain with member roles.
