LACP Configuration

Difficulty: Advanced · Estimated time: 30 min

Link Aggregation Control Protocol (LACP) allows you to bond multiple physical network interfaces into a single logical link, providing increased bandwidth and redundancy. In this lesson you will configure LACP bonds on OpenStack using the Neutron API through the lab framework.

Objective

LACP configuration must be applied to the node before deploying an instance, so that network interfaces are properly aggregated. This guide explains how to configure a node (physical server) in OPCP to enable LACP (Link Aggregation Control Protocol)

Warnings

  • A standard user cannot configure LACP themselves. You must be admin, or have node available in your OpenStack project.
  • It is recommended to configure LACP before deploying an instance. This guide does not cover configuring a node already in production.

Why Use LACP?

LACP can be used in two specific use cases:

  • Increase network capacity: By aggregating multiple network cards, you can add the bandwidth of each card added to this aggregate for the same networks.
  • Increase resilience: Each OPCP server benefits from 4 25G interfaces. Each server is connected to two network switches (A&B) to ensure resilience in case of hardware failure of one of them. LACP allows creating resilient virtual interfaces in case of hardware failure by aggregating two network cards connected to different switches.

Configuration

Node Configuration

1. Transfer Node Ownership (Admin Only)

An admin can transfer ownership of a node to a given project: 

openstack baremetal node set <node-id> --owner <project-id>

2. List Network Ports

Each physical network card, called Network Interface Card (NIC), of a node is represented in OpenStack by a port.

To display the list of ports associated with a node:

3. Enable Maintenance Mode

Before any network configuration modification, the node must be placed in maintenance mode. This ensures that this node cannot be deployed during the operation: 

openstack baremetal node maintenance set <node-id>

4. Create a Port Group (LACP Bond)

The port group allows enabling LACP aggregation between multiple network interfaces.

Success: You can create:
  • a single port group for a 1×4 bond, or
  • two port groups for 2×2 bonds.

Use the --mode 802.3ad parameter to enable LACP.

The --address <MAC> parameter must be equal to the MAC address of the PXE port if it is used. Otherwise, you can omit the parameter or set the MAC address from one of the physical interfaces you will use.

You can list all ports with openstack baremetal port list --node <node-id> --long and check if PXE is used or not. 

openstack baremetal port list --node <node-id> --fields pxe_enabled uuid address

Note: It is recommended to prefix the port group name with the node name (e.g. <node-name>-<name>) to facilitate identification. In this exercice, to ease the cleanup at the end of it, we will omit the node name in following example.

Example:

openstack baremetal port group create \
  --node <node_uuid> \
  --name ${STUDENT_ID}-pg-lacp \
  --mode 802.3ad \
  --address e0:9d:73:79:bb:7c

5. Associate Ports with the Group

Each port of the node must be associated with the created port group: 

openstack baremetal port set --port-group `<port-group-id>` `<port-id>`

Example:

openstack baremetal port set --port-group d082c2ab-5960-44e3-920d-3d6dfb6811e9 068a06b2-ebf9-48c9-a3c3-94016ca5e3da
openstack baremetal port set --port-group d082c2ab-5960-44e3-920d-3d6dfb6811e9 4937d704-7517-4525-86d1-abecb94a7ce9
openstack baremetal port set --port-group d082c2ab-5960-44e3-920d-3d6dfb6811e9 422eece6-dcfa-40cd-975d-ba8bb11c774e
openstack baremetal port set --port-group d082c2ab-5960-44e3-920d-3d6dfb6811e9 34073903-92ad-47d1-a751-15aa96991415

8. Disable Maintenance Mode

Once the configuration is complete, disable maintenance mode: 

openstack baremetal node maintenance unset `<node-id>`

Summary of Steps

Step Action Command
1 List nodes openstack baremetal node list
2 Transfer ownership openstack baremetal node set <node-id> --owner <tenant-id>
3 List ports openstack baremetal port list --node <node-id>
4 Enable maintenance mode openstack baremetal node maintenance set <node-id>
5 Create LACP group openstack baremetal port group create --node <node-id> --name <port-group-name> --mode 802.3ad
6 Associate ports openstack baremetal port set --port-group <port-group-id> <port-id>
7 Disable maintenance mode openstack baremetal node maintenance unset <node-id>
8 Create instance openstack server create --image <image-name> --nic net-id=<network-1> --flavor <flavor-id> --key-name <keypair-name> --availability-zone "nova::<node-id>" <instance-name>

Conclusion

You have configured:

  • The LACP (802.3ad) at the OpenStack Baremetal node level;
  • The bonding configuration in the guest OS;
  • And validated the network performance via iperf3.

Your instance is now ready to exploit all available bandwidth of the aggregated link.

Summary

  • LACP (802.3ad) bonds multiple ports into a single logical link.
