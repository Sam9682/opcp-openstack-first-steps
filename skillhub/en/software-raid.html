Software RAID Configuration

Difficulty: Advanced · Estimated time: 25 min

This section explains how to configure and manage software RAID (software RAID) on an OpenStack Ironic node in your OPCP environment.

Software RAID allows you to create a redundancy configuration at the software level, without requiring a dedicated hardware RAID controller. This solution is particularly useful for improving the availability and storage performance of your instances.

What you will be covered:

  • Configuring software RAID via the Ironic agent interface
  • Verifying the RAID configuration
  • Best practices for managing software RAID

Important: Software RAID configuration must be performed before deploying an instance on the node. Once an instance is deployed, modifying the RAID configuration requires deleting the instance and reconfiguring the node. Creating or modifying a RAID erases data on the disks used.

Software RAID monitoring is the responsibility of the end customer. We do not have access to the deployed instance to manage monitoring. It is recommended to set up an alerting system (for example using the command mdadm --monitor) and integrate this monitoring into your existing monitoring tools.

Why Use Software RAID?

Software RAID offers several advantages in an OPCP environment:

  • Data redundancy: Protection against data loss in case of disk failure.
  • Improved performance: Distribution of read/write operations across multiple disks.
  • Reduced cost: No need for a dedicated hardware RAID controller.

Implementation

1. Check Available Disks on the Node

Before configuring RAID, you need to identify the available disks on your node.

List available nodes:

openstack baremetal node list

Check hardware properties of the node:

openstack baremetal node show <node-id>

2. Enable Maintenance Mode

Before any configuration modification, place the node in maintenance mode:

openstack baremetal node maintenance set <node-id> --reason "Software RAID configuration"

3. Supported RAID Levels

Ironic supports several software RAID levels. The following values are accepted in the JSON configuration:

RAID Level JSON Value Description Minimum Number of Disks
RAID 1 "1" Mirroring 2

Important constraint: The first logical disk with is_root_volume: true must be mandatory in RAID 1. Other RAID levels (RAID 0, 5, 6, 10, etc.) are not allowed for the root volume.

Therefore, only RAID 1 can be used for instance deployment.

4. Configure Software RAID

Ironic allows you to configure software RAID via the agent interface. This configuration is applied automatically during instance deployment.

4.1. Check and Activate Agent Interface if Necessary

Before configuring RAID, check the currently configured RAID interface on the node:

openstack baremetal node show <node-id> -f json | jq '.raid_interface'

If the output is null or different from "agent", activate the agent interface for RAID:

openstack baremetal node set <node-id> --raid-interface=agent

4.2. Create RAID Configuration File

Create a JSON file containing the desired RAID configuration. Here's an example to create a RAID 1 (mirroring) with two disks:

cat > /tmp/raid1.json <<EOF
{
  "logical_disks": [{
    "controller": "software",
    "size_gb": "MAX",
    "raid_level": "1",
    "is_root_volume": true,
    "physical_disks": [
      {"size": "<1000"},
      {"size": "<1000"}
    ]
  }]
}
EOF

The parameter "size": "<1000" in physical_disks allows you to automatically select disks smaller than 1000 GB. You can adjust this value according to the size of your disks or use other selection criteria.

4.3. Apply RAID Configuration

Once the configuration file is created, apply it to the node:

openstack baremetal node set <node-id> --target-raid-config /tmp/raid1.json

4.4. Verify RAID Configuration

To verify the RAID configuration applied on a node:

openstack baremetal node show <node-id> -f json | jq '.target_raid_config'

5. Disable Maintenance Mode

Once the RAID configuration is complete, disable maintenance mode:

openstack baremetal node maintenance unset <node-id>

Summary

  • Configure RAID before deployment: Configuration must be performed on a node without an active instance.
  • Use maintenance mode: Always place the node in maintenance before any modification.
  • Regular backups: RAID is not a backup solution; perform regular backups of your data.
  • RAID monitoring: Set up RAID monitoring (for example via mdadm --monitor) and integrate alerts into your monitoring tools to detect quickly any degradation or disk failure.
  • Performance: Software RAID can impact CPU performance compared to hardware RAID.
  • Compatibility: Not all operating systems support all software RAID levels.
  • Reconstruction: RAID reconstruction after disk replacement can take time and consume resources.
